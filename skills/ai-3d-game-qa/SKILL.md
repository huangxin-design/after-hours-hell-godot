# 排查 AI 辅助 3D 游戏的接入问题

先记录玩家在哪个版本、操作和画面遇到问题。取同一场景和角色的可比样本，固定机位、分辨率和触发步骤。已经有日志或逐帧记录时，先用它缩小范围。若需要运行游戏，遵守当前项目的启动与隔离约定。

## 从现象选检查点

| 现象 | 先检查什么 | 怎样验证修正 |
| --- | --- | --- |
| 道具看得懂，功能位置却对不上 | 原点、轴向、尺度、碰撞、出口或铰点的局部变换。确认哪些部件要独立移动。 | 在引擎里从玩家看到的出口触发一次。对比第一帧出现的位置、实际移动方向和碰撞点。 |
| 静态姿势正常，动起来穿插或脱离 | 在预备、接触、收势及混合途中采样。检查装备挂点和接触面，例如手掌与锅柄、身体与椅背。 | 同时检查接触近景与关卡镜头。技能涉及替身或闪避时，记录命中实体、生命值和状态恢复。 |
| 选角图停稳后正常，打开瞬间有闪烁或错姿 | 把初始骨骼姿态与贴图就绪时间分别核对。保留展示前后连续帧。 | 从冷启动进入、切走再切回、激活卡片分别取样。把第一张可见帧和稳定帧并排，覆盖原问题所在显示模式。 |
| 单个机关能动，串起来走不通 | 从常规走位接近，检查预警位置、碰撞与可站区域、过桥路线及失败后的状态重置。 | 用不同技能的代表角色检查通过、受击、重试与继续前进。分别保存玩家的输入、机关事件和实际落脚画面。 |
| 编辑器正常，导出包异常 | 确认提取出的包、资源清单、版本哈希和启动方式。对照项目中实际加载的字体、材质、动画和地图。 | 从该包启动条件开始查，覆盖故障场景和相邻状态。涉及交付时记录一条从选角到结算的完整路线。 |

单次崩溃保留异常栈、硬件、驱动、图形后端和包哈希。在授权范围内复用同包和同路线复查。若重试未复现，保留首轮失败并注明本次复查结果。只有可控对照支持时才把某个组件写成根因。

每条结论记录 **现象 → 证据 → 改动 → 复查 → 尚待验证**。资产预览支持模型结论，逐帧实机支持显示与动作结论，规则或日志支持状态结论。手感、持续性能和实际试打各用对应证据。缺少运行条件时交付静态结果和可执行的复现步骤。

需要参照真实案例和验收样例时，读[《地狱也得下班》制作复盘](references/after-hours-case.md)。
